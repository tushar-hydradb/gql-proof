# a constant number of variables beyond which nothing more is covered

> for agents: dated working notes, terse on purpose. people start at the [readme](../README.md)

the engine caps how many variables one label holds (`Caps`, `--slots`). raising
the cap costs a lot (fixed point 0.04 s, 0.67 s, 12.8 s, 266 s at 1 to 4) and
can never by itself prove we are done. this is the argument for a constant `c*`
per coverage criterion such that no larger cap covers more, so stopping at `c*`
loses nothing. it turns bernot, gaudel and marre's regularity hypothesis, which
in their work is an assumption, into a theorem for this rule, and says where it
stays an assumption

## where the idea comes from

- **regularity and uniformity** (bernot, gaudel, marre, software engineering
  journal 6(6), 1991, doi 10.1049/sej.1991.0040; gaudel and le gall, lncs 4949,
  2008, arxiv 0804.0970). an exhaustive test set is cut down by hypotheses:
  regularity (correct up to a size means correct for all), uniformity (one test
  per subdomain). the size limit is chosen from knowledge of the program and is
  never proved; gaudel and le gall report a fault beyond the chosen bound
- **data independence and cutoffs**. a program that only compares values for
  equality behaves the same under any renaming, so a bounded number of values
  stands for all (wolper, popl 1986; lazić and nowak, concur 2000). a register
  automaton with `k` registers is nonempty iff it accepts a word over `k + 1`
  values (kaminski and francez, tcs 134, 1994; bojańczyk, klin, lasota, lmcs
  10(3), 2014). parameterized model checking states the same shape, "for all n
  iff for all n up to a cutoff" (emerson and kahlon, cade 2000). the cutoff
  comes from how many values the system must tell apart at once, not from input
  size
- **the fold**: `sum := term (op sum)*` covers nothing new with a third operand
  that it did not with two. this is uniformity with the label as the subdomain,
  and the reason is below

## setup

- labels are synthesized only and hold variables as slots up to renaming
  (`src/context.rs`). so the rule only ever compares variables for being the
  same one, through links, never by name: it is data independent in wolper's
  sense
- `Cov_k(c)`: the targets of a criterion (productions, cdrc pairs, k-paths) used
  by some valid tree whose labels hold at most `c` variables
- a variable is **distinct-required** where the rule refuses to make it one with
  another live variable. in scope these are exactly (`src/context/scope.rs`):

  - variables with an identity flag (`vf::IDENTITY`): a return or select
    column's alias, a name in a CALL scope clause, a pattern's YIELD item, a SET
    or REMOVE target, a LET, FOR or definition's new name, a spelled name, a
    record field
  - declarations that may not join: path variables, variables of a selective
    path pattern, an inserted element with more than its name, everything under
    INSERT (`joined_decl`, `joinable`), and one subpath variable per pattern
  - references inside a CALL scope clause (`listing` in `combine`)

  every other meeting of two variables, two references, a reference and its
  binder, two node or edge declarations that may join, is an equality the rule
  allows to be the same variable

## theorem

1. **monotone**: `Cov_k(c) ⊆ Cov_k(c + 1)`. the cap only filters labels, so a
   larger cap keeps every tree a smaller one has
2. **collapse**: take a valid tree that covers target `t`. two live variables
   that are not distinct-required can be made one (the rule allows it, and the
   target is syntax, untouched). a subtree can be swapped for any other with the
   same label: labels are synthesized, so the rest of the tree cannot tell.
   repeated folds (`a + b + c`) pump down to the shortest repetition whose
   labels repeat
3. **what is left**: after collapsing, the only variables still apart are
   distinct-required ones the witness cannot avoid. in this grammar they come in
   lists (`item (, item)*`), where every item is a new distinct variable. the
   cap applies to every label, a production's partial labels included, so what
   counts is the widest step, not the item count. call `w` the slots one item
   holds at its widest step: 1 for a list whose items meet their binder one at a
   time, 2 for a YIELD list, whose references sit beside the pattern's
   declarations until the binding table discharges them
   - a production of a list: the recursive step `rep2 ::= , item rep2` needs the
     list's first item, that step, and the step that ends it: **3w**, but the
     step that ends a list of two (`, item`) and `opt ::= rep2` need **2w**
   - a cdrc pair: the same step used inside itself needs one more item: **4w**
     for the recursive step, **3w** for the ending one
   - a k-path running `j` times down a list's recursion: **(j + 2)w**
4. so `c*` (productions) is `max 3w`, `c*` (cdrc) is `max 4w` over the lists the
   rule forces apart. for scope that is 4 for productions (YIELD, `2w`) and 6
   for cdrc pairs (YIELD inside itself, `3w`), and for `c >= c*`,
   `Cov(c) = Cov(c*)`

the assumption it rests on, and the one way it can be wrong: the list of
distinct-required variables above must be complete. a rule that keeps two
variables apart without showing up in that list would let a target need more
than the bound. that is exactly what measuring one cap past `c*` catches

## evidence

`coverage_by_cap` in `tests/context_scope.rs` builds the grammar at each cap and
counts what it can derive:

```
cap  productions   cdrc pairs   two-step chains   time
1    2,094         3,679        6,880             0.2 s
2    2,124 (+30)   3,736 (+57)  6,976 (+96)       3.9 s
3    2,133 (+9)    3,755 (+19)  7,044 (+68)       76 s
4    2,135 (+2)    3,769 (+14)  7,092 (+48)       27 min
```

every production cap 3 adds is a list of distinct-required items gaining its
recursive step: SET and REMOVE items, LET definitions, RETURN and SELECT items.
cap 4 adds those lists' recursive step inside itself (the predicted cdrc pairs,
for SET, REMOVE, LET, RETURN and SELECT), and two productions the first version
of this doc did not predict: a YIELD list of two items
(`<graph pattern yield item list/rep2> ::= , item` and `opt1 ::= rep2`). that is
what measuring past the bound is for: the yield references sit beside the
declarations they name in the binding table's partial label, so each item costs
two slots, and the theorem above now counts slots per item instead of items

prediction for the next caps: nothing new at 5; at 6 the YIELD list's recursive
step and its pair inside itself, then nothing. cap 5 alone is hours at today's
speed, so this stays a prediction until emission is faster or the binding table
discharges each yield item as it is read (which makes `w = 1` and `c* = 4` for
everything)

## what stays a hypothesis

- the scope rule's readings (it forbids more than iso; see its module doc), the
  height cap of the generator, and types and the catalog, not in the engine yet:
  each needs its own distinct-required list when ported
- k-paths beyond the bound above: emission keeps one instance per (production,
  position, child label), so `research/totality-2026-10-21.md` does not prove
  k-paths are emitted at all; the cutoff for them is an upper bound on
  variables, not a proof of coverage
