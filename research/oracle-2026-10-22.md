# oracles and the graphs they run against

today a run checks one thing: whether an engine accepts a sentence. the oracle
step turns each sentence into a test case, a graph, the query and an expected
outcome (a bag of rows, no result, or an exception condition), so a run says
whether the answer was right. this note is the plan; the roadmap's data and
oracle items point here

## where the sentences stand

what a graph has to exercise, from the cached sets in `sentences/`:

- fixed hops: the longest chain of concatenated edges in a MATCH is 3
  (`MATCH <- <- <- FINISH`), most have 0 or 1. that is the cutoff again: path
  concatenation is a list, its production needs 2 elements and its cdrc pair 3,
  so coverage asks for no more. hops are anonymous edges, the variable cap does
  not bound them
- variable hops: 207 MATCHes of the typed turbolay set carry `*`, `+`, `?` or
  `{m,n}`, so how far they go is up to the data
- engine thresholds sit past both: turbolay names every hop from 2, reverses the
  anchor only at 1, and stops at 16 (`max_traversal_hops`) and 255 (u8) hops. 1
  to 3 reach the first two; 16 and 255 need a forcing knob or explicit graphs
  (see the linear doc on keeping the proof valid while turbolay gets fast)

## the graphs, defined per query

the query fixes what a useful graph looks like, so graphs are generated with the
sentence and stored beside it (`graphs` in the sentence's jsonl line), in our
own json: nodes with labels and properties, edges with a type, a direction and
properties. emitters write each engine's native bulk load, not gql INSERT, so
setting the graph up never depends on the INSERT under test

- **witness**: freeze the MATCH pattern into data. a node per node pattern with
  its labels and the property values its predicates need, an edge per edge
  pattern with its type and direction, a quantified edge as a chain at its
  minimum length and one more. the query must return at least one row
- **near misses**: the witness with one element changed (an edge dropped, a
  direction flipped, a label changed, a property moved across a predicate's
  boundary). each must change the result, usually to empty. this is data
  coverage, every predicate made true and false, null included (xdata, chandra
  et al.; qagen, binnig et al.; sqlfpc's mc/dc as the adequacy measure)
- **small exhaustive**: every graph up to about 3 nodes and 3 edges over 2
  labels, up to isomorphism (the small scope hypothesis, jackson). the data side
  of the variable cutoff: self loops, parallel edges, short cycles and
  disconnected parts all appear at that size
- **solver built**, later: a graph per partition of a query's predicates, from
  the obligations record the context provider can emit (variables and their
  classes, labels and properties needed, which must be equal or differ), with z3
  as xdata and qagen do. the witness above is the case with no solver

the witness costs no search: it is read off the tree the generator emitted, and
the context engine already knows each variable's kind and class

## expected outcomes, in phases

each test is tagged with the tier that backs it

1. **partial oracles, no evaluator**. witness gives at least one row; near miss
   gives a different result; metamorphic relations: tlp (rows with p, with not p
   and with p is null add up to all rows, rigger and su), isomorphic graphs give
   the same bag, a disconnected component leaves an anchored query alone, a
   pattern reversed with its directions gives the same matches. cheap, finds
   real bugs, claims consistency, never correctness
2. **reference evaluator for a core**: single MATCH patterns, FILTER, RETURN,
   aggregates, ORDER BY, written from the general rules literally, slow and set
   based, the way the checkers follow the syntax rules: independent of every
   engine. check mgql (lean) and gpml-conformance first, they may cover the
   pattern core already (`research/prior-art-2026-10-20.md`)
3. **exception conditions**: the dynamic must raise / may raise / never raises
   classification (use after delete raises 22G11 on any graph with a row,
   `DATE ( { } )` raises 22G05 on any graph). neither mgql nor gpml-conformance
   models exceptions, and they are half of the totality claim
4. **grow the core**: data modification, paths, the rest of the expressions

## comparing

- bags, order only under ORDER BY
- node and edge identities differ per engine: compare by a canonical key, a test
  only id property or the labels and properties
- nulls as nulls
- exceptions by class: the runs so far already show right refusals with wrong
  codes (`EXISTS { FINISH }` refused with 0A000 at plan time instead of 42000)

## open questions

- the graph format and loaders per engine (turbolay's loader, neo4j's)
- whether the reference evaluator is ours or mgql through an emitter to lean
  terms; the roadmap leans to mgql for the read only core, ours for the rest
- how many graphs per sentence before the run cost matters: witness and near
  misses are a handful, exhaustive ones are hundreds and shared across sentences
