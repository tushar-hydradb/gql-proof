# totality of the context engine at a fixed number of variables

what we can prove about the grammar `src/context.rs` emits for a rule (scope
today), what we
cannot, and the evidence behind both. the claim is relative: to the rule as
written, to the
cap on variables, and to the generator's height cap. it is not a claim about iso
itself,
which the rule reads more strictly in the places its module doc lists

## setup

- `G`: the grammar the engine runs on: iso's bnf desugared (`src/cfg.rs`),
  refined by the
  syntax rules and the claim (`src/refine.rs`). its productions are `q, p, ...`,
  each with an
  id in the unrefined grammar (`unrefined`) and an occurrence per right hand
  side position
  (`occ`)
- `R`: the rule, a `Context` (`src/context/scope.rs`). for a production `q` it
  gives
  `empty(q)`, then `push(q, i, partial, child)` per position, then `finish(q,
  partial)`, each
  a finite set of labels (a rule may choose). the cap `k` (`Caps { slots,
  references }`) is
  part of `R`: a label holding more than `k` variables is not one
- a labelling of a tree of `G` gives each node a label such that some run of
  `push` from
  `empty(q)` over the children's labels, then `finish`, yields it. a tree is
  **valid** when it
  has a labelling whose root label is a top (`R::top`)
- `V`: the set of valid trees. "at most `k` variables" means exactly this: every
  label in the
  labelling holds at most `k`

## assumptions

- **a1, the rule is finite.** for a fixed `k`, each nonterminal has finitely
  many labels.
  true for scope: a label is at most `k` variables, each from a finite
  descriptor, and a
  finite set of flags
- **a2, the rule is synthesized.** a node's labels depend only on its production
  and its
  children's labels: no inherited state. true by the `Context` interface
- **a3, liveness is sound.** `project` drops a fact only where no ancestor reads
  it, and
  rejects only where every ancestor that could read it rejects. this is a
  property of the fact
  table in `Scope::facts`, checked by testing (every generated tree passes the
  independent
  checker; the corpus differential), not by proof
- **a4, the generator is exact on what it is given.** purdom and the targeted
  trees
  (`src/purdom*.rs`) cover every production, cdrc target and k-path of the
  grammar they get,
  within the height cap, and report the rest (needs more height, or never)

## lemma 1: the fixed point is exact

for every nonterminal `N`, `labels(N)` after the fixed point is exactly the set
of labels of
valid labellings of trees of `N`

- **sound:** every label enters through `finish` over a complete partial label,
  which entered
  through `push` over labels already in `labels(child)`. induction on when it
  entered gives a
  tree (the back pointers in the layers are that tree)
- **complete:** induction on the height of a tree `t` of `N` with label `L` via
  production
  `q`. its children's labels are in `labels(child)` (induction). the partial
  labels of `q` are
  kept between scans; every pair (partial label at position `i`, child label) is
  pushed once
  both exist: if the child label came later, the child's nonterminal changed, so
  `q` was
  marked and rescanned with that label among its new options; if the partial
  label came
  later, it was new in that scan and met every option. so the run that labels
  `t` is in the
  layers, and `finish` adds `L`
- only new labels trigger rescans; a smaller witness of a known label does not.
  that changes
  sizes, never the sets

## lemma 2: every label of a valid tree is reached in emission

emission interns, from the top label down, one nonterminal per label it reaches.
claim: for a
valid tree `T` with labelling `λ`, every `λ(n)` is reached

induction from the root. `λ(root)` is the top and is reached first. let `n` be
reached, with
production `q`, and `c` its child at position `i`. the option `(q, i, λ(c))` is
taken by some
emitted instance whose parent label is reached:

- the single pass gives each option its smallest instance into some label `L*`
  of `q`'s left
  hand side. if `L*` is ever reached, that instance is emitted and `λ(c)`
  interned
- otherwise the option stays open, and the fallback runs `q` again against the
  reached labels
  of its left hand side, each time that set has grown, until nothing new is
  reached. the last
  run sees the final set, which holds `λ(n)`, and `T` shows `λ(n)` admits `λ(c)`
  at `i`, so
  the pass finds an instance and takes the option

so `λ(c)` is interned, and by induction every label of `T` is

## theorem 1: productions

every production that occurs in some valid tree is in the emitted grammar

let `q` occur at node `n` of `T ∈ V`. `λ(n)` is reached (lemma 2). when it is
expanded,
`smallest(q, λ(n))` exists, since `T` gives `q` a run to `λ(n)` (lemma 1), and
is emitted

## theorem 2: cdrc pairs

every (occurrence, production) pair, a production `p` used at occurrence `o` of
a production
`q`, that occurs in some valid tree is in the emitted grammar

`o` is position `i` of `q`, and its child `c` has label `λ(c)`. by lemma 2's
argument the
option `(q, i, λ(c))` is taken by an emitted instance of `q`; `λ(c)` is reached,
and
`smallest(p, λ(c))` is emitted under it (theorem 1's argument). the emitted
grammar has both,
and every emitted nonterminal is productive and reachable, so a tree of it uses
the pair

## corollary: sentences

with a4, the generator's trees cover every production and cdrc target that some
valid tree
uses within the height cap, and report the rest. with the naming pass and the
per tree check
(`verify::scope`), every printed sentence is valid

## what is not proven: k-paths for k of 3 or more

a 3-path `q1 -o1-> q2 -o2-> q3` needs one emitted instance of `q2` whose label
is one `q1`
takes at `o1` and which takes, at `o2`, a label that has `q3`. emission keeps
one instance
per (production, position, child label) with some reached parent, not one per
parent label,
so the `q2` instance below `q1` can be a different one from the instance that
has `q3` below
it. a valid tree can then use a chain the emitted grammar cannot derive. closing
it costs
either the per parent label instances emission dropped for speed (the x800 cost
the
instrumented runs showed), or a targeted search per k-path in
`purdom/targeted.rs` that asks
the engine for a chain directly

## evidence

- **toy, exhaustive** (`tests/context.rs`, `bounded_exhaustive_completeness`):
  every tree of
  the let/use toy up to height 9, 9,330 trees, 363 valid. their 9 productions
  and 11 cdrc pairs
  are exactly the emitted grammar's, nothing missing, nothing extra
- **turbolay#261 corpus** (`tests/context_scope.rs`, `corpus_uses_are_emitted`):
  11,493
  distinct queries, 9,023 valid at 3 variables by the rule. they use 1,049
  productions, 1,539
  cdrc pairs and 2,001 two-step chains, all in the emitted grammar. so the
  k-path gap above did
  not show on real queries
- **generated trees pass the independent checker**: 984, 858 and 860 trees at 1,
  2 and 3
  variables, every one passing `verify::scope`, and `purdom` prints nothing
  unless all do.
  this is the check on a3
- **neo4j** (`just neo4j`, 3 variables, the neo4j claim): 92 of 481 run. no
  refusal names one
  of our variables; the refusals are type errors (136, the types rule is not
  ported yet), gql
  syntax and functions neo4j does not implement (about 200), and catalog names
  (25)

## what totality is relative to

- the rule: scope's readings forbid more than iso (no correlated subqueries, no
  declarations
  under quantifiers, aggregates only as a return item's own, and the rest in its
  module doc).
  totality is over the rule's language, which is a subset of iso's
- the cap: trees whose labels hold at most `k` variables. a construct that needs
  more live
  variables at once than `k` is outside, and it shows as an uncovered target,
  not as a silent
  loss
- the height cap of the generator: targets that need taller trees are reported
  by name
- types and the catalog: not in the rule yet, so sentences are valid in scope,
  not in type
